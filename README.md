# Time Tracker

A basic, single-user Windows desktop app for manually tracking time on tasks and projects.
Create projects and tasks, start and stop a timer on a task (or add time by hand), and see
lifetime totals per task and per project in hours and minutes, plus an entry history. Data is
stored locally in one JSON file. No account, no network, no telemetry.

**Stack:** Tauri 2 (Rust backend) + React/TypeScript UI. Rules and persistence live in the
Tauri-free crate `crates/tracker-core`; `src-tauri` is a thin shell around it.

## Prerequisites (Windows)

- [Rust](https://rustup.rs) (stable, MSVC toolchain)
- Node.js 20 or newer
- Visual Studio **Build Tools** with the "Desktop development with C++" workload (MSVC)
- WebView2 (already part of Windows 11 and current Windows 10)

## Build and run

```powershell
npm install
npm run icons        # once: generates src-tauri/icons from a placeholder source image
npm run tauri dev    # development, with hot reload
npm run tauri build  # release build
```

`npm run tauri build` produces:

- a portable executable: `target/release/tracker.exe` (needs WebView2 to be present), and
- a per-user NSIS installer under `target/release/bundle/nsis/` (it installs WebView2 if it is
  missing; that needs a network connection at install time only).

The built app embeds the UI, so it needs no dev server. `npm run icons` writes an icon set
(from `app-icon.svg`); to use your own, run `npx tauri icon path/to/your-image.png` and commit
`src-tauri/icons`.

> Lockfiles: `package-lock.json` and `Cargo.lock` are generated by the first `npm install` and
> `cargo build`. Commit them.

## Tests

```powershell
cargo test -p tracker-core   # rules, persistence, recovery, restart acceptance flow
npm test                     # UI component tests with a stubbed backend
npm run lint                 # tsc --noEmit
```

## Where the data lives

`%APPDATA%\dev.tracker.timetracker\data.json` (format: [docs/data-format.md](docs/data-format.md)).
Logs (warnings and errors only, no names or notes) are in the app log folder.

> **Never change the bundle identifier `dev.tracker.timetracker`** in
> `src-tauri/tauri.conf.json` after the first release. It determines the data folder; changing it
> orphans existing data. A test pins it.

## Manual smoke checklist for the packaged exe

1. Launch `tracker.exe`: it opens to an empty state asking for a first project.
2. Create a project and a task. Start the timer, wait a few seconds, press Stop: the task and
   project totals increase.
3. Start a timer, close the app, reopen it: the timer is still running and elapsed time counts
   from the original start.
4. Add a manual entry with Add time; edit and delete an entry; delete a task and a project and
   check the other totals are unchanged.
5. Close the app, replace `data.json` with garbage, relaunch: the recovery screen names a backup
   copy and offers "Start with empty data".
6. Make `data.json` unreadable (for example open it with an exclusive lock, or replace it with a
   folder of the same name): the screen shows the message and a Retry button only.
7. Launch a second instance: the existing window is focused and no second window opens.
